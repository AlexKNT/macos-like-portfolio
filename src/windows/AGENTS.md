# src/windows

The window bodies: what a window shows once the shell has opened it. A body reads the target it was handed, reads the content layer, and paints inside a frame the shell has already placed. Nothing here positions, sizes or moves a window, and nothing here decides which window opens: that is `src/store` and `src/components`.

Governing specs: [`0005-projects-window`](../../docs/specs/0005-projects-window/index.md) for the Finder and the two file windows, [`0003-desktop-shell`](../../docs/specs/0003-desktop-shell/index.md) for the registry it introduced, [`0006-content-window-bodies`](../../docs/specs/0006-content-window-bodies/index.md) for the standard every body is built to, [`0007-resume-window`](../../docs/specs/0007-resume-window/index.md) for the document window and the page it paints on, [`0008-contact-window`](../../docs/specs/0008-contact-window/index.md) for the address, the copy pair and the social tiles, [`0010-gallery-window`](../../docs/specs/0010-gallery-window/index.md) for the album sidebar, the grid and the viewer a window can hold inside itself, [`0011-articles-window`](../../docs/specs/0011-articles-window/index.md) for the list of posts and the date it prints, and [`0012-archive-window`](../../docs/specs/0012-archive-window/index.md) for the Archive, its own gesture and the control it puts in the title bar.

## Files

- `WindowBody.tsx`: the one place a window id becomes a body. The props a body is given (the window id, the window key, the target), the props its own scope is given (the same three plus `children`), the entry shape (a `Body`, an optional `Lead` and an optional `Trail` for the two ends of the title bar, and an optional `Scope`), and the `WINDOW_BODIES` record. Read it first.
- `ItemTile.tsx`, `itemTarget.ts`: the one face the desktop gives an entry of its file tree (the file's own icon above its own name, a button when the press stays in the app and a real anchor when it leaves) and where a press on one leads. The Finder's grid and the Archive's block both draw through them, so the two windows cannot drift apart. A tile that stops answering takes the native `disabled` as a button, and `aria-disabled` with `tabIndex={-1}` and no pointer events as an anchor, which has no `disabled` of its own.
- `WindowStage.tsx`: the container every body is built in: the `@container` context, the optional sidebar slot, the one named content area (a `group`, `tabIndex={-1}`, the padding) and the stage's single polite live region.
- `QuietLine.tsx`: the one way a window shows an empty, missing or refused thing, promoted out of the Finder's folder so every body shares it.
- `copyLines.ts`, `copyState.ts`, `CopyConfirmation.tsx`, `useCopyText.ts`, `useLineReveal.ts`: the copy pair (its words, the state the confirmation renders from, the confirmation, the hook that writes through `#lib/clipboard`) and the staggered reveal the Skills window prints with.
- `projects/`: the Finder (`ProjectsWindow`, `FinderSidebar`, `FinderGrid`, `ProjectDetail`, `PitchContent`), the window's own state (`projectHistory`, `useProjectHistory`, `ProjectHistoryScope`, `ProjectBackButton`), the two file bodies (`TextFileBody`, `ImageFileBody`), and the Finder's own words (`quietLines`).
- `skills/`: the terminal window (`SkillsWindow`, `TechStack`, `TechGroupRow`, `outcomeForRow`, `skillsLines`).
- `resume/`: the document window (`ResumeWindow`, `useResumeFile`, `resumeLines`), the first body with an async read: its hook owns the state and the check lives at the edge.
- `contact/`: the contact window (`ContactWindow`, `SocialTile`, `contactLines`) and the mail link it builds (`mailLink`).
- `gallery/`: the photos window (`GalleryWindow`, `AlbumSidebar`, `PhotoGrid`, `PhotoTile`, `PhotoViewer`), its own state (`galleryState`, `useGalleryState`) and its own words (`galleryLines`). The folder keeps its own context file: [`gallery/AGENTS.md`](gallery/AGENTS.md).
- `articles/`: the blog list (`ArticlesWindow`, `ArticleRow`, `articlesLines`), its order and the date it prints (`articleOrder`, `articleDate`). No state, so no `Scope` and no title bar control.
- `archive/`: the desktop's bin (`ArchiveWindow`, `ArchiveEmptyLine`, `ArchiveEmptyButton`, `ArchiveScope`), its own three moment state (`archiveState`, `useArchiveState`), the one movement that empties it (`useEmptyMovement`) and its own words (`archiveLines`). The registry's first `Trail`.
- `projects/fileFromTarget.ts`: the file a target names, or `null` when it names none or names one that is not there. A file window's target carries the file's id rather than the file itself, so the file is looked up when the body renders and there is one truth about what it holds.

## Conventions

- A window feature edits its own line in `WINDOW_BODIES` and touches nothing else, so no window feature has to know about the desktop surface. The `Record<WindowId, WindowBodyEntry>` annotation is what makes a window id with no body a typecheck failure rather than a blank window.
- A body is a pure function of what the manager holds. It reads the target it was handed, asks `#content/reads` for what that target names, and reports a missing entry as a value (`Result` or `null`), never a throw.
- The target names what to show, so a window on a place and a window on a file are one mechanism. `Place` is a member of `openTargetSchema`, which is why the Finder looks the same whether a desktop icon, a dock button or a menu bar link sent the visitor there.
- React reserves `key`, so the instance key travels as `windowKey`. A body that changes what its own window shows calls `open(target, { kind: 'window', key: windowKey })`: the same instance with a new target. That is how the Back control works, and why a second open never makes a second window.
- Window state the manager does not own (the Finder's place history, the Archive's gesture) lives in the window, in a component registered as the entry's `Scope`, wrapped around the frame so the title bar reads that state through one provider. Nothing about it is stored twice: the place showing is the instance's target, and the Archive's moment is dropped with its window.
- The registry exposes a control for each end of the title bar: `Lead` beside the three lights and `Trail` past the window's name, both rendered by `ManagedWindow` into the frame's own `leading` and `trailing` slots. A window with chrome of its own registers it there rather than reaching into the frame.
- A window frame is already a named `region`, so a body's content area is a named `group`. Two nested regions carrying one name break every role and name query and read as a stutter in a screen reader's landmark list. The registry baseline counts a body's named `group`s, so a further named container inside a body is a `figure` named by the thing it shows, never a second `group` or a nested landmark.
- The frame owns Escape and the arrow keys, which close and move the window. A body that shows something Escape should close first answers those keys on its own element and stops them there, or the window closes out from under it.
- A body renders exactly one `WindowStage`, which is what carries the container query, the content area's padding and the one polite live region. A body adds content and words only, never a second padding or a live region of its own, and the registry baseline test holds it.
- Anything outside the page (a file the site serves, the clipboard) goes through one function at the edge that returns a `Result` rather than throwing, with a hook beside the body owning the state it produces. The body itself holds no path, no request and no browser API.
- A body that paints on `--color-surface-paper` stays on the page set (`design.md`), because the paper is white in both modes while the ordinary tokens flip.
- Every literal a visitor reads lives in one pure words module for that window (`quietLines.ts`, `skillsLines.ts`, `resumeLines.ts`, `copyLines.ts`, `contactLines.ts`, `galleryLines.ts`, `articlesLines.ts`, `archiveLines.ts`), each function named for the state it describes rather than for where it appears on screen.
- A control that becomes unavailable takes `aria-disabled` and keeps its place in the tab order, never the native `disabled`: disabling a focused control drops the keyboard to the body the moment it is disabled. The window's own machine is what makes a press in that state a genuine no op, and the control can show the same thing to the eye through the muted ink rather than by dimming the element, which would weaken the focus ring with it.
- A window whose place can hold nothing asks the count as well as the moment (`canEmpty(state, count)`), and the same predicate guards the press, so a window that opened on an empty place answers nothing rather than running a gesture over nothing.
- Import through the aliases (`#content`, `#lib`, `#store`, `#windows`), keep one job per module, export names only, and give every exported thing a short comment saying what it does.
- The accessibility bar holds here as it does everywhere: a control is a button with an accessible name, an image keeps its `alt` text even when its asset never loads, and a state that replaces content is text a screen reader can read.
